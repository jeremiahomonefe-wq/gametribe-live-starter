# Game Tribe Live - starter 0.1

A web-first, realtime multiplayer quiz starter. This is a development scaffold, not a production-ready service.

## What's implemented in this starter

- Host creates a game and receives a 6-digit PIN.
- Guests join with a nickname and PIN; no account required.
- Host starts the quiz, advances questions, and reveals answers.
- Server owns the game state, question timer, answer acceptance, and scoring.
- One answer per player per question; late answers are rejected.
- Projector/player views update through Socket.IO.
- Player reconnect tokens are generated by the server and stored in the current browser tab session.
- Refreshing or reconnecting can restore the same player identity, score, and submitted-answer state while the server process is still running.
- Disconnected players remain in the game roster and are marked offline; their scores and answers are retained for the session.
- Automated tests cover core game rules and reconnect behavior.

## Not implemented yet

- Persistent database (sessions and quizzes are in memory and disappear when the server restarts).
- Cloud-saved quizzes and accounts, QR-code rendering, moderation tools, analytics, payments, or multi-server scaling.
- Proof of 500-player capacity. A load test is a later milestone; do not market this starter as tested for 500 concurrent players.

## Release 0.2 additions (from the PRD)

- Server locks each question at its deadline (state `locked`), then reveals the answer about 2 seconds later with no host action. The host can still reveal earlier, and always presses Next. Late answers are rejected.
- Answers carry the question index, so an answer for an old question is rejected.
- Host can end the game at any time; answers stop immediately.
- Projector is its own read-only screen. The host button opens `/#projector=<PIN>` in a new tab; it receives public state only and cannot send host commands.
- Host dashboard shows how many players have answered. Players see a correct / not this time / no answer result card (sent privately, never in public state).
- Nicknames allow letters, numbers, spaces and `- _ . '`.
- Joining, reconnecting and projector lookups are rate limited per connection (12 attempts per 30 seconds).
- Event handling lives in `server/src/hub.js`, separate from Socket.IO, and is covered by tests.

## Host recovery and quiz builder

- The host's game PIN and host token are kept in the browser tab. After a refresh or a dropped connection the host reconnects with `host:reconnect` and keeps control of the same game. Players and the projector see "The host lost connection" until then. The game and its timers keep running meanwhile.
- A late close event from an old host connection is ignored, so it cannot mark a returned host offline.
- Quiz builder: create, edit, duplicate and delete quizzes; 2 to 4 answers, one correct answer, a time limit per question, move or duplicate questions. Limits and messages come from `server/src/quiz-rules.js`, shared by the editor and the server, which validates every quiz again before a game starts.
- A live game uses a copy of the quiz taken at launch.
- Quizzes are saved in the browser (localStorage) until accounts and a database exist (PRD 1.0). They do not follow the user to another device.

## Put it online (one deploy)

After `npm run build`, the Node server also serves the website, so players and the game share one address and no cross-origin settings are needed. The lobby shows a QR code and the host can copy a join link.

- **Render (easiest):** push this folder to GitHub, create a new Blueprint or Web Service from it. `render.yaml` is included. Build command `npm install && npm run build`, start command `npm start`. Free plans sleep when idle, so open the site a few minutes before an event.
- **Docker (Fly.io, Railway, any VPS):** `docker build -t gametribe-live .` then `docker run -p 4000:4000 gametribe-live`.
- **Same Wi-Fi, no internet:** `npm install && npm run build && npm start`, then players open `http://<your-laptop-ip>:4000`. Allow the app through the laptop's firewall.
- Run exactly one instance: games live in that server's memory, so a restart ends them.
- Use HTTPS online. Phones and the clipboard features need it, and the QR link uses whatever address the host page was opened on.
- Development is unchanged: `npm run dev` (server on 4000, site on 5173).

## Pages and addresses

- `/` home: host a demo quiz, build a quiz, or join a game.
- `/#join` the player page. "Join a game" opens it, the browser back button leaves it, and it can be opened directly.
- `/#join=123456` the same page with the game PIN already filled in (use this for the link or QR code later).
- `/#projector=123456` the read-only projector screen for that game.

## Scoring (documented rule)

- Correct answer: 500 points plus up to 500 for speed (linear over the question time). Wrong or no answer: 0.
- Leaderboard order: score (high to low), then nickname (A to Z). Tied top scores are shown as a tie.

## Preview build

`npm run build:preview` writes `preview-dist/preview.html`, a single file with the server simulated in the browser (host, projector and phone side by side). It reuses the real game engine and hub.

## Requirements

- Node.js 20+ (tested locally with Node 22)
- npm

## Run locally

From this directory:

```bash
npm install
npm run dev
```

Open the Vite URL shown in the terminal, usually `http://localhost:5173`. Open it in two or more browser tabs to simulate a host and players. Choose a role on each tab. For a phone on the same Wi-Fi, configure Vite to listen on your LAN and set `VITE_SERVER_URL` to your computer's LAN address; see `.env.example`.

## Manual reconnect test

1. Start the app with `npm run dev` and create a game in one browser tab.
2. Join from a second tab using a nickname.
3. Start the quiz and submit an answer.
4. Refresh the player tab. It should restore the same player in the active game without asking for the PIN again.
5. Confirm the score and submitted-answer state remain intact. Try to submit another answer for the same question; the server should reject it.
6. Repeat after advancing to another question and after briefly disconnecting/reconnecting the network.

Reconnect data is kept in server memory. Restarting the server clears games and invalidates reconnect tokens. `sessionStorage` is scoped to that browser tab; opening a different tab does not automatically inherit the session.

## Environment

For server settings, copy `server/.env.example` to `server/.env`. For the browser server URL, copy `client/.env.example` to `client/.env`. Vite exposes only variables prefixed with `VITE_` to the browser.

## Project layout

```text
server/
  src/game-engine.js   Server-authoritative rules and state transitions
  src/quiz-rules.js    Quiz limits and validation shared by server and editor
  src/hub.js           Event handling, rate limits, question timers (no Socket.IO inside)
  src/index.js         HTTP + Socket.IO transport and event validation
  test/game-engine.test.js
client/
  src/App.jsx          Host, projector, and player views
  src/main.jsx         React entry point
  src/styles.css       Game Tribe brand styling (cream, tomato red, orange, yellow, ink)
```

## Security and reliability notes

This is a prototype. Before public deployment, add rate limits, nickname/content validation policy, host-token expiry and rotation, durable storage, structured logs, origin/CORS restrictions, operational monitoring, and abuse protection. The host token is a development credential and should not be treated as a complete production authentication system.
